# Before making the repository public

This folder is prepared for GitHub, but the project owner should review these items before publishing:

- [ ] Choose a repository owner/name, then add an appropriate GitHub description and topics.
- [ ] **Choose a source-code license** and add a top-level `LICENSE` file. The supplied project contained none; this package intentionally does not invent one.
- [ ] Decide whether to publish source only or also attach release builds. CI artifacts are short-lived development artifacts, not signed releases.
- [ ] Review every source file, dependency/framework use, acknowledgements, trademarks, and private-API usage.
- [ ] Confirm the code and any included third-party fragments are yours to publish. The project directory’s README describes touch-surface lineage and `Support/MultitouchBridge.h` comments; check applicable upstream license/attribution obligations before public release.
- [ ] Do not upload `config.json`, personal backups, `.DS_Store`, build outputs, signing identities, certificates, or private logs.
- [ ] Decide how security issues should be reported privately; update `SECURITY.md` with an actual contact channel instead of the placeholder guidance.
- [ ] Enable GitHub Actions and Wiki if desired; confirm the workflow runs on GitHub’s current macOS runner images.
- [ ] Test a fresh clone from the README instructions.

This checklist is practical preparation, not legal advice.
